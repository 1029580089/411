# 序工 · Workshop Planner

一个以浏览器为界面的生产工单计划工具。输入设备产能、停机日期、库存、BOM 和工序路线，输出可解释的工单计划、缺料原因、延期风险及设备负荷。

本项目于 2026-10-01 新建，是独立代码作品，尚未用于企业生产环境。样例数据用于演示约束和验算，不代表实际订单。

## 运行

需要 Node.js 20 或更新版本；没有第三方运行或测试依赖，无需 npm install。

```sh
npm test
npm run check
npm start
```

打开 http://127.0.0.1:4173 。如端口被占用，可以通过 PORT 环境变量指定其他端口。本地服务仅监听回环地址，不接受数据写入。

## 使用与复现

打开后自动加载五张工单。默认样例应该得到 2 张按期、1 张延期、2 张不可排：WO-1003 缺 20 单位 STEEL，WO-1005 因其前置工单不可排而阻塞。WO-1002 因 CNC 的产能占用及 10 月 3 日停机，预计 10 月 4 日完工。

可以尝试把 stock.STEEL 从 100 改成 120 并重新排程，检查缺料及其下游依赖是否解除；然后增加设备停机日期，观察新的交期。编辑后旧计划立即失效，避免错误地导出上一版结果。导出 CSV 只包含当前有效的工单汇总。

输入存在于浏览器内存中；刷新会重新载入样例。页面不包含分析服务、第三方字体或数据上传接口。

## 算法与业务边界

1. 完整校验输入：ID、范围、整数、真实日期、物料与设备引用、依赖存在性及环。
2. 从前置工单已有结果的候选工单中，按优先级降序、交期升序、ID 升序选择下一张。
3. 校验前置工单状态和当前剩余库存。
4. 在临时产能副本上逐道工序排程。全部工序成功后才一次性提交物料及产能预留；失败不留下部分占用。
5. 返回每道工序的日级分配、汇总与明确阻塞原因。

采用自然日时间桶，工时单位为整数分钟。工序允许跨天，下一工序和依赖工单最早在前项完工的次日开始；这是一项保守建模约束。周末不自动休息，必须在 downtime 中显式配置。库存仅表示计划起始时可使用的原料，前置工单不会自动增加成品库存。校验通过但超出计划窗口的工单归为产能/窗口不足。

此实现为确定性的贪心启发式，不保证总延期或设备利用率全局最优，不处理采购到货、换型、拆单、在制品、人员班次或动态插单。支持最多 200 工单、20 设备、90 天、每工单 10 道工序。设备负荷视图同时展示停机与已占用时间。

## 代码结构

| 路径 | 职责 |
| --- | --- |
| planner.mjs | 输入校验、依赖检查、齐套检查、排程、CSV |
| index.html / app.mjs / style.css / sample.json | 中文界面与可复现样例 |
| server.mjs | 固定白名单静态文件服务 |
| *.test.mjs | 算法、不变量、输入校验和 HTTP 集成测试 |

核心算法为无 I/O 的纯函数，浏览器与 Node 测试直接使用同一模块。输入不被修改，输出不依赖系统时钟。日期采用 UTC 日序，避免夏令时导致天数偏差。界面使用 textContent 渲染输入，不执行 HTML；CSV 对公式前缀做转义。服务器禁止非 GET/HEAD 请求，只有明确列出的资源可访问。

## 验证

测试覆盖样例预期、库存竞争、依赖链、停机、释放日期、跨日工序、事务回滚、日期及引用校验、CSV 公式前缀和 HTTP 文件访问边界。另使用固定随机种子生成 100 组工作负载，检查库存守恒、产能不超限和分配工时守恒。测试结果以实际运行输出为准。
